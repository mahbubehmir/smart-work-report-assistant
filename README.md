# دستیار هوشمند ثبت و پیگیری گزارش‌های کاری

این پروژه یک ربات تلگرام مبتنی بر Python است که گزارش‌های کاری فارسی را به زبان طبیعی دریافت می‌کند، اطلاعات موردنیاز را با کمک مدل زبانی استخراج می‌کند و در پایگاه داده SQLite ذخیره می‌کند.

هدف پروژه، ساده‌سازی ثبت گزارش‌های روزانه و فراهم کردن امکان بازیابی و تحلیل گزارش‌های کاری است.

## قابلیت‌های پروژه

- دریافت گزارش‌های کاری به زبان طبیعی فارسی، بدون نیاز به قالب مشخص
- استخراج نام گزارش‌دهنده، تاریخ گزارش، کارهای انجام‌شده و مشکلات
- استفاده از مدل زبانی برای تحلیل متن گزارش
- ذخیره گزارش‌ها در پایگاه داده SQLite
- مشاهده پنج گزارش اخیر کاربر
- پشتیبانی از مدل محلی Ollama و امکان استفاده از OpenAI API
- نگهداری متن اصلی گزارش برای مراجعه‌های بعدی

## فناوری‌های استفاده‌شده

- Python
- Telegram Bot API
- python-telegram-bot
- Ollama و مدل Qwen3
- OpenAI API به‌صورت اختیاری
- SQLite
- Requests
- python-dotenv

## پیش‌نیازها

برای اجرای پروژه به موارد زیر نیاز است:

- Python نسخه 3.10 یا بالاتر
- Git
- توکن ربات تلگرام از طریق `@BotFather`
- برای استفاده از Ollama: نصب Ollama و در دسترس بودن مدل `qwen3:8b`
- برای استفاده از OpenAI: کلید معتبر API و دسترسی به سرویس

## نحوه نصب و اجرا

### ۱. دریافت پروژه

در ترمینال اجرا کنید:

```bash
git clone https://github.com/mahbubehmir/smart-work-report-assistant.git
cd smart-work-report-assistant
```

### ۲. ایجاد محیط مجازی

در ویندوز:

```bat
python -m venv .venv
.venv\Scripts\activate
```

سپس وابستگی‌های پروژه را نصب کنید:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### ۳. تنظیم متغیرهای محیطی

فایل نمونه تنظیمات را کپی کنید:

```bat
copy .env.example .env
```

سپس فایل `.env` را باز کنید و مقادیر موردنیاز را تنظیم کنید.

نمونه تنظیمات برای استفاده از Ollama:

```dotenv
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here

LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen3:8b

OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o-mini

DATABASE_PATH=reports.db
WEEK_START_DAY=MONDAY
```

مقدار `TELEGRAM_BOT_TOKEN` را با توکن واقعی ربات خود جایگزین کنید.

**نکته امنیتی:** فایل `.env` شامل تنظیمات محلی و اطلاعات محرمانه است و نباید در GitHub منتشر شود.

### ۴. آماده‌سازی مدل هوش مصنوعی

برای استفاده از مدل محلی، Ollama را نصب و اجرا کنید. سپس دستور زیر را اجرا کنید:

```bash
ollama pull qwen3:8b
```

سرویس Ollama باید در آدرس زیر در دسترس باشد:

```text
http://localhost:11434
```

اگر می‌خواهید از OpenAI استفاده کنید، مقدار `LLM_PROVIDER` را در فایل `.env` به `openai` تغییر دهید و کلید API معتبر خود را تنظیم کنید.

### ۵. اجرای ربات

پس از انجام تنظیمات، در پوشه اصلی پروژه اجرا کنید:

```bash
python main.py
```

در صورت راه‌اندازی موفق، پیام آماده‌به‌کار بودن ربات در ترمینال نمایش داده می‌شود.

## نحوه استفاده

۱. ربات تلگرام را باز کنید و دستور `/start` را ارسال کنید.

۲. گزارش کاری خود را به زبان طبیعی فارسی بنویسید و ارسال کنید.

۳. ربات تلاش می‌کند اطلاعات گزارش را استخراج کند و آن را در پایگاه داده ذخیره کند.

۴. برای مشاهده گزارش‌های اخیر خود، از دستور `/myreports` یا دکمه مربوط به آن استفاده کنید.

۵. برای مشاهده راهنما، دستور `/help` را ارسال کنید.

### نمونه گزارش کاری

```text
من رضا هستم. امروز بخش ورود کاربران را تکمیل کردم،
اما به دلیل نداشتن دسترسی به سرور نتوانستم
تست نهایی را انجام دهم.
```

اطلاعات مورد انتظار از این گزارش شامل نام گزارش‌دهنده، تاریخ گزارش، کار انجام‌شده و مشکل یا مانع اعلام‌شده است.

## ساختار پایگاه داده (Database Schema)

پروژه از SQLite برای ذخیره‌سازی دائمی اطلاعات استفاده می‌کند. ساختار پایگاه داده در فایل `database.py` تعریف شده است.

تابع `init_db()` جدول `reports` و دو ایندکس را در صورت وجود نداشتن ایجاد می‌کند.

### جدول `reports`

هر رکورد در این جدول نشان‌دهنده یک گزارش کاری ثبت‌شده است.

| نام ستون | نوع داده | محدودیت | توضیحات |
|---|---|---|---|
| `id` | INTEGER | کلید اصلی، افزایش خودکار | شناسه یکتای گزارش |
| `telegram_user_id` | INTEGER | NOT NULL | شناسه تلگرام کاربر ثبت‌کننده |
| `employee_name` | TEXT | NOT NULL | نام گزارش‌دهنده |
| `report_date` | TEXT | NOT NULL | تاریخ گزارش با قالب `YYYY-MM-DD` |
| `completed_tasks` | TEXT | NOT NULL | فهرست کارهای انجام‌شده به شکل JSON |
| `problems` | TEXT | NOT NULL | فهرست مشکلات و موانع به شکل JSON |
| `original_message` | TEXT | NOT NULL | متن اصلی گزارش ارسالی کاربر |
| `created_at` | TEXT | NOT NULL | زمان ذخیره گزارش با قالب ISO 8601 |

### ایندکس‌های پایگاه داده

برای بهبود عملکرد پرس‌وجوها، دو ایندکس تعریف شده است:

- `idx_reports_date`: روی ستون `report_date` برای جست‌وجو بر اساس تاریخ و بازیابی گزارش‌های یک بازه زمانی.
- `idx_reports_user_date`: ایندکس ترکیبی روی ستون‌های `telegram_user_id` و `report_date` برای بازیابی گزارش‌های هر کاربر بر اساس تاریخ.

### روش ذخیره‌سازی اطلاعات

- ستون‌های `completed_tasks` و `problems` از نوع `TEXT` هستند و فهرست‌ها در قالب آرایه JSON ذخیره می‌شوند.
- هنگام تبدیل فهرست‌ها به JSON از `ensure_ascii=False` استفاده می‌شود تا متن فارسی حفظ شود.
- ستون `original_message` متن اصلی گزارش را نگهداری می‌کند.
- `report_date` تاریخ مربوط به فعالیت گزارش‌شده را مشخص می‌کند.
- `created_at` زمان واقعی ذخیره گزارش در پایگاه داده را ثبت می‌کند.
- اتصال پایگاه داده، بررسی کلیدهای خارجی SQLite را فعال می‌کند؛ اما در ساختار فعلی رابطه‌ای با کلید خارجی تعریف نشده است.

### توابع مدیریت پایگاه داده

| تابع | کاربرد |
|---|---|
| `init_db()` | ایجاد جدول و ایندکس‌ها |
| `save_report()` | ذخیره گزارش و برگرداندن شناسه آن |
| `get_user_reports()` | دریافت گزارش‌های یک کاربر؛ پیش‌فرض پنج گزارش |
| `get_recent_reports()` | دریافت آخرین گزارش‌های ثبت‌شده در سیستم؛ پیش‌فرض هفت گزارش |
| `get_weekly_reports()` | دریافت گزارش‌های هفته شامل دوشنبه تا یکشنبه |

| `config.py` | بارگذاری تنظیمات محیطی |
| `handlers.py` | مدیریت پیام‌ها و تعاملات تلگرام |
| `services.py` | استخراج اطلاعات با استفاده از مدل زبانی |
| `database.py` | ایجاد، ذخیره و بازیابی داده‌ها |
| `keyboards.py` | ساخت دکمه‌های رابط کاربری |

## مدیریت اطلاعات و امنیت

- فایل `.env` نباید در مخزن GitHub قرار گیرد.
- فایل دیتابیس محلی `reports.db` از نسخه‌بندی Git مستثنا شده است.
- برای اجرای پروژه، هر کاربر باید توکن ربات و تنظیمات موردنیاز خودش را وارد کند.
- اطلاعات واقعی گزارش‌های کاری نباید بدون مجوز در اختیار اشخاص دیگر قرار گیرند.

## نکته درباره گزارش هفتگی

در لایه پایگاه داده، تابع `get_weekly_reports()` برای بازیابی گزارش‌های هفته وجود دارد. فعال بودن فرمان و قابلیت نمایش خلاصه هفتگی در تلگرام به اتصال این تابع به منطق برنامه بستگی دارد.
